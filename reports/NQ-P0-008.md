# NQ-P0-008 付费能力封闭与支付安全回归报告

完成日期：2026-09-22  
结论：**已按“关闭付费能力”方案完成并通过验收**

## 任务目标

在可信支付核验上线前，保证空 TXID、任意 TXID、伪造哈希或管理员手工操作都不能获得付费资产，也不能触发创作者结算；重复请求不得产生重复权益或余额变化。

## 实施决策

项目当前没有链上节点、区块浏览器 API、支付网关、签名 Webhook、确认数检查或按订单生成的收款信息。管理员目视 TXID 不能证明币种、网络、目标地址、金额和确认数均正确。

因此本项没有把字符串格式检查包装成“支付核验”，而是关闭全部付费下单和批准能力。免费产品继续领取；后续只有接入可信服务端支付核验后才能重新开放付费能力。

## 修复前风险

- 空 TXID 会被替换为 `TX_HASH_PENDING` 或 `CHAIN_TX_UNCONFIRMED` 并创建 pending 订单。
- 任意字符串都能作为支付凭据进入人工审核队列。
- 管理员账号购买付费产品会直接完成订单并增加作者余额。
- 管理员可以目视任意 TXID 后批准，订单立即变为 completed 并结算作者。
- 订单批准使用先查后改，缺少条件更新和明确结算标记。
- 用户资产列表包含 pending/rejected 订单；详情页可能把任何订单误显示为已购买。
- 下载接口只检查 completed，没有区分免费授权与经过服务端支付核验的付费授权。

## 已实施修复

### 1. 服务端关闭付费下单

- `/api/orders` POST 仍要求有效 Session，并从数据库读取产品与价格。
- 当数据库价格大于 0 时固定返回 HTTP 503。
- 客户端提交的 `txHash`、`status`、`payment_verified` 等字段不会被保存或采信。
- 删除管理员购买直接完成和给作者加余额的免检旁路。
- 付费请求不会创建 pending/completed 订单，也不会改变任何余额。

### 2. 关闭人工批准和结算

- `/api/orders` PATCH 的 `approve` 动作固定返回 HTTP 503。
- 代码中已经没有把付费订单改为 completed 或增加作者余额的可调用路径。
- 重复 approve 请求始终零状态变化、零余额变化。
- 管理员仍可驳回历史 pending 订单；驳回使用立即事务和 `WHERE status = 'pending'` 条件更新，重复驳回返回 HTTP 409。

### 3. 增加付费权益隔离字段

订单表新增：

- `payment_verified`：服务端支付验证标记，默认 0。
- `verified_at`：支付验证时间，默认空。
- `settled_at`：创作者结算时间，默认空。

当前没有 API 能把付费订单的 `payment_verified` 设置为 1，也没有 API 写入 `settled_at`。

### 4. 强化资产库和下载鉴权

用户订单列表和下载接口都要求：

```sql
status = 'completed'
AND (price = 0 OR payment_verified = 1)
```

因此历史上即使存在 `completed` 的付费订单，只要没有服务端支付验证标记，也不会进入用户资产库并且不能下载文件。

### 5. 免费授权保持可用且幂等

- 免费产品仍可通过 POST 领取。
- 免费授权由服务端写入固定的 `FREE_LICENSE`，不采信客户端 TXID。
- 使用立即事务和 `(username, product_id)` 唯一索引；并发领取只保留一个订单。
- 重复领取返回既有订单，不会重复创建记录或产生结算。
- 免费订单不写入 `settled_at`，不会给作者增加余额。

### 6. 数据库约束

新增唯一索引：

```sql
CREATE UNIQUE INDEX idx_orders_one_per_user_product
ON orders(username, product_id);

CREATE UNIQUE INDEX idx_orders_unique_tx_hash
ON orders(tx_hash)
WHERE tx_hash IS NOT NULL
  AND tx_hash <> ''
  AND tx_hash <> 'FREE_LICENSE';
```

第一项阻止同一用户对同一产品生成多笔订单；第二项为未来可信支付核验保留 TXID 防重放约束。

### 7. 前端关闭付费入口

- 删除加密货币地址、TXID 输入框和“我已完成支付”收银台。
- 付费产品按钮显示“付费购买维护中”且不可点击。
- 后台删除“确认到账”按钮，显示付费审批和结算已关闭的提示。
- 后台只保留驳回历史待处理订单的操作。

## 修改文件

- `app/api/orders/route.js`：关闭付费下单/批准、免费授权幂等、订单列表权益过滤。
- `app/api/download/route.js`：付费下载增加 `payment_verified` 条件。
- `lib/db.js`：新增支付验证/结算字段与订单唯一索引。
- `app/page.js`：移除收银台和 TXID 提交流程。
- `app/components/MarketView.js`：禁用付费产品购买按钮。
- `app/admin/page.js`：移除人工到账确认，保留条件驳回。

## 重新开放付费前的必要条件

重新开放付费入口必须同时完成：服务端创建支付意图、固定币种和网络、按订单确定金额与收款地址、验证支付服务 Webhook 签名、核对链上目标地址/币种/金额/确认数、以 TXID 和回调事件 ID 防重放、条件更新 `payment_verified`、同一事务内写入不可变账本并只结算一次。

在这些能力完成前，应保持 `PAID_CHECKOUT_ENABLED = false`，不得恢复人工“确认到账”按钮。
