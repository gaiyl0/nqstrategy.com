# NQ-P2-003 修复报告：EA 版本管理、更新日志与购买权益继承

完成日期：2026-09-27  
状态：已完成代码、隔离数据库测试、生产运行时接口回归、生产构建和实际数据库迁移。

## 问题

旧模型只在 `products.file_url` 保存一个程序路径。开发者更新程序时会解绑旧文件，并把旧文件放入 24 小时孤儿回收队列。这会覆盖发布历史，使买家无法确认下载版本，也无法表达“全部已有买家继承”或“仅新买家获得”的升级政策。下载记录只知道产品，不能证明实际下发了哪个二进制版本。

## 验收标准

1. 产品支持多个不可变版本，每个版本独立保存程序文件、SHA-256、版本号和更新日志。
2. 同一产品不能重复版本号，同一上传文件不能绑定多个版本。
3. 已提交版本的文件身份、摘要、版本号、权益政策和更新日志不能被覆盖。
4. 新版本只能由管理员审核后发布；发布切换当前版本必须原子且幂等。
5. 买家权益由服务端根据订单、版本和升级政策计算，客户端不能指定自己有权下载。
6. 历史买家在无新版本权益时仍可下载自己有权获得的历史版本。
7. 下架版本保留版本记录与既有下载审计，程序文件不进入孤儿回收。
8. 下载审计记录版本 ID、产品 ID、用户 ID、订单 ID 和下载时间。
9. 旧产品只在上传记录和 SHA-256 来源完整时迁移为初始版本。

## 已完成修复

### 数据模型

新增 `product_versions`：

- 稳定 `product_id` 外键；
- 产品内唯一版本号；
- 唯一上传 ID 和唯一私有文件 URL；
- 程序 SHA-256；
- 不可变更新日志；
- `all_existing` 或 `new_purchases_only` 权益政策；
- `pending / published / rejected / retired` 状态；
- 单产品唯一当前版本；
- 提交人、审核人、提交时间、审核时间、发布时间、拒绝或下架原因。

新增 `product_version_downloads`，每次成功下发文件都记录具体版本和使用的订单权利。

数据库触发器阻止在版本提交后修改产品、版本号、上传 ID、文件 URL、SHA-256、权益政策、更新日志、提交人和创建时间。`new_purchases_only` 的权益截止时间只允许在待审版本首次发布时写入一次。

### 开发者发布流程

新产品现在必须同时提交：

- 初始版本号；
- 初始版本说明；
- 升级权益政策；
- EX4/EX5 私有上传文件。

初始版本先处于 `pending`，管理员批准产品时在同一审核流程中发布初始版本。已经发布的程序不能再通过“编辑产品”覆盖。开发者需要在“我发布的策略”中打开“提交新版本”，填写版本号、更新日志、权益政策并上传新程序。

新版本只允许提交到开发者自己的活动产品；普通用户、其他开发者和未登录请求均被拒绝。接口使用现有 Session、CSRF/Origin、分层限流和结构化审计。

### 管理员审核与并发控制

管理员可在策略后台查看所有版本，并执行发布、拒绝和下架。

发布使用 SQLite `IMMEDIATE` 事务：

1. 条件检查版本仍为 `pending`；
2. 清除原当前版本标志；
3. 条件更新目标版本为 `published + is_current=1`；
4. 对新购限定版本写入一次性发布时间截止点；
5. 更新产品兼容字段 `file_url`。

重复发布相同版本返回 `replayed`，不会再次切换或生成第二个当前版本。并发下只有一个条件更新能改变状态，数据库局部唯一索引保证一个产品最多有一个当前版本。

下架当前版本时会原子回退到最近的其他已发布版本；没有可回退版本时产品不再提供当前下载，但版本和下载历史仍保留。

### 权益继承

支持两种不可变版本政策：

- `all_existing`：该产品所有有效拥有者都可下载，包括版本发布前购买的用户。
- `new_purchases_only`：只有版本实际发布时间之后形成的有效订单可以下载该版本。

有效订单仍必须是 `completed`，且必须为免费授权或已经可信支付核验的付费订单。订单状态、用户 ID、产品 ID、支付核验和购买时间都从数据库读取。

旧买家没有新购限定版本权益时，资产库仍列出其有权下载的历史版本，不会因为当前版本升级而失去原文件。

### 安全下载

`/api/download` 现在接受产品 ID 和可选版本 ID：

- 未指定版本时选择当前已发布版本；
- 指定版本时只接受属于该产品的已发布版本；
- 服务端重新核验作者、管理员或有效订单权益；
- 上传记录必须同时匹配版本的上传 ID、产品 ID、URL 和 SHA-256；
- 文件路径仍由私有存储根目录和数据库存储名解析；
- 下载文件名包含真实版本号；
- 响应包含 `X-Nexus-Version-Id`；
- 成功读取并准备下发时写入版本下载审计。

### 市场与资产库

市场策略详情展示：

- 所有公开版本；
- 当前版本标志；
- 版本 SHA-256 前缀；
- 更新日志；
- 每个版本的升级权益政策。

用户资产库展示当前版本，并为该订单有权获得的每个历史或当前版本提供独立下载按钮。

## 边界

- 当前版本号校验接受常见数字点分版本和可选预发布后缀，但没有自动判断语义版本大小；管理员仍决定发布顺序。
- `new_purchases_only` 是明确的商业政策，不是推荐默认值。默认应选 `all_existing`，避免已有买家意外失去升级权。
- 已下架版本记录和程序文件会保留以维护下载审计；后续需要独立的数据保留政策，不能直接使用孤儿上传清理。
- 真实付费仍处于关闭状态。未来恢复支付时，新订单的生效时间必须取可信支付结算时间，而不是客户端时间。
- 正式数据库迁移框架仍属于暂停中的 NQ-P1-010；本次继续采用备份加启动迁移标记。
