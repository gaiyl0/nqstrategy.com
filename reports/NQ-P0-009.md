# NQ-P0-009 稳定用户身份与账户匿名化报告

完成日期：2026-09-22  
结论：**已完成并通过验收**

## 任务目标

停止使用可变、可复用的用户名作为资产所有权依据。用户删除后即使使用原用户名和邮箱重新注册，新账户也不能继承旧账户的订单、产品、收入、帖子、评论、上传文件或提现身份。

## 删除与匿名化策略

账户删除改为匿名化注销：

1. 保留原 `users.id`，作为历史业务记录的稳定身份和审计锚点。
2. 将用户名和邮箱改为包含原 ID 与随机后缀的唯一匿名值，避免与现有账户冲突。
3. 将角色改为 `deleted`，写入 `deleted_at`。
4. 用不可登录的随机值替换密码，清空头像和邮箱验证状态。
5. 增加 `session_version`，立即撤销已有 Cookie 会话。
6. 产品、订单、帖子、评论和提现中的展示名改为 `Deleted User #<id>`，同时保留对应用户 ID。
7. 保留历史余额、订单和资金记录用于审计；重新注册账户从新 ID 和零余额开始。
8. 用户名和邮箱在匿名化后可以重新注册，但不会与旧记录建立关系。

应用层不再物理删除用户。新增外键使用 `ON DELETE RESTRICT`，避免以后误删用户行破坏审计链。

## 数据模型迁移

新增字段：

| 表 | 稳定身份字段 |
|---|---|
| `users` | `deleted_at` |
| `products` | `author_user_id` |
| `orders` | `buyer_user_id` |
| `posts` | `author_user_id` |
| `comments` | `author_user_id` |
| `withdrawals` | `user_id` |

五个业务身份字段都建立到 `users(id)` 的 SQLite 外键，删除策略为 `RESTRICT`。

订单唯一约束从 `(username, product_id)` 迁移为 `(buyer_user_id, product_id)`；单用户 pending 提现唯一约束从 `username` 迁移为 `user_id`。产品、帖子和评论增加用户 ID 检索索引。

## 历史数据迁移策略

- 迁移执行时，只有能与当时存在的活跃用户明确匹配的文本身份才回填用户 ID。
- 本次实际回填了管理员名下的 1 个产品、1 个订单、1 个帖子和 1 条评论。
- 现有 2 个孤儿产品、2 个孤儿订单和 3 个孤儿帖子无法确认原用户，身份字段保持 `NULL`。
- 写入 `settings.migration_user_id_v1 = completed` 作为一次性迁移标记。
- 后续启动不会再次按用户名匹配孤儿记录，防止未来同名注册者在重启后认领历史资产。

专门回归了该边界：在迁移标记完成后注册名为历史孤儿作者 `AlgoMaster` 的测试用户，再重启数据库初始化代码，原产品的 `author_user_id` 仍为 `NULL`。

## 接口迁移

### 产品与上传

- 创建产品同时写入 `author_user_id`。
- 编辑、删除、自有产品判断全部比较用户 ID。
- 前端“我发布的策略”通过 `author_user_id === user.id` 识别。
- 上传文件继续通过 `uploads.owner_user_id` 校验；同名新用户不能复用旧用户上传文件。

### 订单、资产库和下载

- 创建订单同时写入 `buyer_user_id`。
- 查询个人订单使用 `buyer_user_id`。
- 禁止购买自己产品使用 `author_user_id`。
- 下载权限使用产品作者 ID 或订单买家 ID，不再比较用户名。

### 帖子和评论

- 新帖子、新评论同时写入作者用户 ID。
- 作者资料联表通过 ID 完成。
- 删除帖子和评论的所有权判断使用用户 ID。

### 提现和退款

- 提交、查询和 pending 唯一约束使用 `user_id`。
- 驳回退款使用提现记录中的 `user_id` 更新原账户余额。
- 删除后发生的退款会进入旧匿名账户，不会进入同名新账户。

### 用户改名和注销

- 改名时只按稳定用户 ID 更新展示快照，不再通过旧用户名跨表匹配。
- 管理员用户列表统计产品和帖子数量时使用用户 ID。
- 所有用户管理操作都拒绝已注销账户。
- 登录、密码重置和 Session 恢复都排除 `deleted_at` 非空的用户。

- `app/api/orders/route.js`：订单所有权迁移为买家用户 ID。
- `app/api/download/route.js`：作者和买家下载权限迁移为用户 ID。
- `app/api/posts/route.js`：帖子作者和所有权迁移为用户 ID。
- `app/api/comments/route.js`：评论作者和所有权迁移为用户 ID。
- `app/api/withdraw/route.js`：提现身份和退款目标迁移为用户 ID。
- `app/page.js`：个人产品和发帖统计使用用户 ID。

## 后续边界

- 匿名账户中保留的余额需要后续制定财务人工核销、退款或法务保留期限；当前策略优先保证资金不会转移给新账户。
- 历史孤儿记录若要恢复归属，必须由管理员依据外部证据执行显式 ID 迁移，禁止恢复用户名自动匹配。
- 本项完成用户身份外键迁移；订单到产品、评论到帖子等其他实体外键和正式迁移工具仍属于后续数据库治理范围。
