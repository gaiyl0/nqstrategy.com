# NQ-P1-004 生产代理信任边界与限流拓扑修复报告

复核日期：2026-09-23

## 问题

旧实现只根据 `TRUSTED_PROXY_MODE` 读取 `CF-Connecting-IP`、`X-Real-IP` 或 `X-Forwarded-For`。生产环境没有强制配置代理模式，也无法证明请求确实经过可信代理。攻击者在可直连源站时可以自行设置转发头并不断伪造 IP；未配置模式时，全部匿名请求又会共用一个来源桶。

限流桶保存在本地 SQLite。旧配置没有声明实例拓扑，部署人员可能把应用扩展到多个独立实例，并误以为每个实例各自的 SQLite 限流能够形成全局限制。

## 验收标准与结果

| 验收标准 | 验证结果 | 结论 |
|---|---|---|
| 明确可信入口模式 | 生产环境必须显式选择 `nginx`、`cloudflare` 或 `forwarded` | **已完成** |
| 只读取可信入口覆盖的来源头 | 每个模式只读取一个指定头；拒绝逗号链、非法 IPv4/IPv6 和其他模式的头 | **已完成** |
| 证明请求经过可信代理 | 代理必须注入至少 32 字符的 `X-Nexus-Proxy-Secret`，应用使用定时安全比较 | **已完成** |
| 直连或伪造头不能绕过 IP 限流 | 密钥缺失或错误时忽略声称的 IP，并映射到同一个失败关闭来源桶 | **已完成** |
| 未配置时安全失败 | 生产 `next build`、`next start` 和模块加载会因缺少代理配置而失败 | **已完成** |
| 明确限流存储和实例拓扑 | 当前只允许 `RATE_LIMIT_BACKEND=sqlite` 和 `DEPLOYMENT_TOPOLOGY=single-instance` | **已完成** |
| 阻止误用多实例 | SQLite 配置声明多实例或其他未实现后端时拒绝生产启动 | **已完成** |
| 提供部署、验证和回滚说明 | 已新增生产入口、Nginx 示例、上线验证、密钥轮换和多实例升级要求 | **已完成** |

NQ-P1-004 的代码和单实例部署基线已经完成。仓库中没有真实服务器、DNS、防火墙或代理配置，因此公网源站隔离和生产代理注入只能在正式部署环境执行最终验收，不能由本地代码证明。

## 支持的生产拓扑

```text
Internet -> TLS edge/reverse proxy -> one Next.js instance -> one local data.db
```

当前版本主动拒绝多实例。若未来需要横向扩展，必须先实现 Redis 或 PostgreSQL 等共享限流后端，并完成跨至少两个实例的原子递增、统一过期、重启持久性和故障策略回归。

## 测试证据

### 配置和来源解析：13/13

- 缺少代理模式、短共享密钥、不支持的模式均被拒绝。
- SQLite 多实例和未实现的非 SQLite 后端均被拒绝。
- 完整单实例配置可以加载。
- 正确密钥下的 IPv4 和 IPv6 被接受。
- 错误/缺失密钥、逗号 IP 链、非法 IP 和错误模式头均不受信任。

### HTTP 真实路由：13/13

- 使用 31 个不同伪造 IP 和 31 个错误代理密钥请求登录。
- 前 30 个请求进入同一个失败关闭来源桶，第 31 个返回 429。
- 使用正确代理密钥的两个来源不受失败关闭桶影响，并获得不同来源摘要。
- 31 个伪造请求的审计记录全部为 `sourceTrusted: false` 和 `proxy_auth_failed`，来源摘要完全相同。
- 3 个可信请求的审计记录均为 `sourceTrusted: true`，来源摘要互不相同。
- 审计数据中不存在代理共享密钥或管理员密码。
- 恢复后的管理员凭据通过真实 `/api/auth/login` 路由登录并返回 `admin` 角色。

## 部署时仍需现场确认

正式发布前必须按 `DEPLOYMENT_SECURITY.md` 逐项确认：

1. 公网只能访问代理，不能直连 Next.js 端口。
2. 代理覆盖来源 IP 头和共享密钥头，不能透传客户端同名值。
3. 审计日志中的正常公网请求显示 `sourceTrusted: true`。
4. 编排平台固定为一个实例且关闭自动扩容。
5. 重启后限流状态仍然存在。

如果实际目标平台要求 Serverless 或多实例，本项不能直接沿用 SQLite 配置，必须先新增共享限流后端。
