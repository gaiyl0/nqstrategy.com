# NQ-P2-001B 修复报告：MT5 HTML 报告自动解析

完成日期：2026-09-27  
状态：代码基线完成；需使用项目所有者真实 MT5 导出报告做格式现场验收。

## 问题与验收标准

截图 OCR 适合核对画面，但无法精确恢复净值、回撤和月度收益。开发者手工录入八项指标和三组曲线也容易出错或作弊。

验收标准：开发者上传 MT5 原始 HTML 报告后自动得到八项指标和三组曲线；页面不再显示手工曲线文本框；产品接口拒绝修改自动提取结果；报告私有保存并记录 SHA-256；刷新后可恢复未绑定报告；没有可解析报告的产品不能新上架。

## 已完成修复

1. 新增 `strategy_reports`，以 `owner_user_id`、`product_id` 和 SHA-256 绑定报告身份，原始 HTML 存入私有目录。
2. 新增 `/api/strategy-report`，限制 `.htm/.html`、10MB、developer/admin、分层限流、CSRF multipart、恶意扫描和审计。
3. 支持 UTF-8、UTF-16 LE/BE 报告；解析中英文常见标签：Initial Deposit、Total Net Profit、Profit Factor、Sharpe Ratio、Recovery Factor、最大回撤、总交易数、盈利交易比例。
   已根据中文 MT5 实际界面补充“初始入金”“复原因子”“盈利交易（% 全部）”等字段，并统一全角/半角冒号、括号和空格。UTF-16 LE 无 BOM 文件也可通过空字节分布识别。
   使用真实 `TianWei_V1.46_Official_2026_REALTICKS.htm` 回归后补充了 MT5 中文翻译“采收率”作为 Recovery Factor，并在同时存在最大结余亏损与最大净值亏损时优先采用净值回撤。
4. 成交曲线解析严格按表头定位 Time、Profit、Commission、Swap；不会把末列 Balance 误识别为利润。缺少明确成交表头或不足两个交易日期时失败关闭。
5. 按成交日期累计 Profit + Commission + Swap，生成净值曲线、已实现回撤曲线和月度收益。报告中的官方最大回撤独立保留，因为它可能包含持仓内浮动回撤，与按已成交记录重建的曲线峰值不同。
6. 开发者选择报告后立即上传解析，八项指标自动回填并锁定；三个手工曲线文本框已删除，改为显示自动生成的数据点数量。
7. 产品 Schema 强制 `reportId`；创建、编辑和管理员上架均重新核对八项指标及三组曲线，任何客户端篡改返回 409。
8. 报告只允许绑定到上传者自己的一个产品；编辑时可保留或替换；产品删除时同步删除私有报告文件。
9. 同一账号刷新后重新选择相同的未绑定报告会返回原报告 ID 和 `resumed: true`，不会重复占用空间。
   未绑定报告超过 24 小时会回收；数据库存在但私有文件丢失时清理失效记录并允许重新上传。
10. 统计截图没有 OCR 时，管理员批准会使用同一产品的 HTML 报告提取值作为交叉核对数据，不再要求手工粘贴 JSON。截图仍需管理员视觉审核。
11. 市场详情和后台显示报告解析器版本与 SHA-256 前缀，公开端不提供原始 HTML 下载路径。

## 边界

- MT5 不同构建版本、语言和导出模板可能使用不同标签；未知格式会失败关闭，不能静默产生近似数据。正式使用前需收集真实报告扩充解析 fixture。
- 当前曲线根据 HTML 成交表重建。报告官方最大回撤可能包含持仓内浮动回撤，因此可能高于已实现成交曲线的最大回撤；界面应分别理解这两个概念。
- HTML 报告提高数据一致性和可追溯性，但文件仍可能由开发者伪造。它对应“MT5 报告已解析”，不是 Nexus 实盘认证。
