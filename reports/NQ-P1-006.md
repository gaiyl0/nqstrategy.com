# NQ-P1-006 账号与邮箱枚举防护修复报告

复核日期：2026-09-26

## 问题与结论

修复前，登录接口对不存在账号返回 404 和“账号不存在”，对错误密码返回 401 和“密码不正确”；重置验证码对不存在邮箱立即返回 404，存在邮箱则进入 SMTP；两个密码重置入口对不存在邮箱也返回专用 404。攻击者无需密码即可批量判断用户名或邮箱是否注册。

本项已完成：未知账号与错误密码返回相同 401 和正文，未知账号执行真实 scrypt 虚拟校验；重置验证码对存在和不存在邮箱返回相同 202、相同正文并设置 750 ms 最低响应时间；密码重置的未知邮箱、无效验证码和状态冲突统一为 400；内部审计继续保存准确原因。

复核中还发现 `banned` 用户没有登录阻断。现已在密码验证成功后拒绝被封禁账号，对外仍返回通用凭据错误，内部记录 `ACCOUNT_DISABLED`。

## 修复位置

| 位置 | 修复内容 |
|---|---|
| `lib/auth.js` | 增加固定有效 scrypt 虚拟哈希和 `verifyPasswordOrDummy`；未知账号执行与正常 scrypt 账号同类的密码计算。 |
| `app/api/auth/login/route.js` | 未知账号和错误密码统一为 401 `{ success:false, message:'账号或密码不正确' }`；先验证密码再披露 `PASSWORD_RESET_REQUIRED`；阻断 `banned` 登录；移除密码重置兼容入口。 |
| `app/api/send-code/route.js` | 重置用途统一返回 202 通用响应；未知邮箱不签发验证码；SMTP 未配置或投递失败也不通过公开响应泄漏账户存在性；所有重置响应至少等待 750 ms。 |
| `app/api/auth/register/password/route.js` | 未知邮箱、验证码缺失/无效/过期及账户状态冲突统一为相同 400 响应；在判断邮箱存在前完成新密码 scrypt，减少计算成本差异。 |
| `app/page.js` | 重置邮件提示改为条件式通用文案；直接调用唯一密码重置路由，不再请求不存在的 `/api/auth/reset-password` 后降级到登录路由。 |
| `lib/validation.js` | 登录路由只使用 `loginSchema`，移除不再使用的登录/重置联合 schema。 |
| `lib/db.js` | 支持 `NEXUS_DB_PATH`，用于将生产运行时回归完全隔离到临时数据库。默认仍使用项目根目录 `data.db`。 |

## 行为说明与剩余边界

重置邮件接口现在采用防枚举通用响应。即使 SMTP 未配置或邮件投递失败，浏览器也会显示“如果该邮箱绑定了账户，验证码将发送”。运维人员必须通过审计和告警发现 `SMTP_NOT_CONFIGURED` 或 `DELIVERY_FAILED`，不能依赖用户界面报告投递故障。

最低响应时间只能降低远程粗粒度时序差异，无法保证不同 SMTP 服务、网络路径和主机负载下达到密码学意义的恒定时间。分层限流和审计仍然是抵御批量枚举的必要组成部分。

注册接口仍会在最终注册时返回合并后的“用户名或邮箱已被注册”。注册流程必须告知身份冲突才能让用户改正输入，而且当前响应不说明用户名还是邮箱冲突；该行为保留，并继续受来源和身份限流保护。
