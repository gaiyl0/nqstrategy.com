# NQ-P1-003 验证码安全存储与原子消费修复报告

复核日期：2026-09-22

## 问题

旧实现使用 `Math.random()` 生成六位验证码，并把明文写入 `verification_codes.code`。注册和密码重置先查询验证码，再单独写业务数据和删除验证码；这组操作不是同一个事务。旧表也没有用途、失败次数、最大尝试次数或消费时间，无法可靠阻止用途混用、暴力猜测、重放及并发重复消费。

## 验收标准与结论

| 验收标准 | 验证结果 | 结论 |
|---|---|---|
| 使用加密安全随机数生成六位验证码 | `lib/verification-codes.js` 使用 `crypto.randomInt(0, 1_000_000)` 并补齐六位 | **已完成** |
| 数据库只保存带服务端密钥的摘要 | 保存 SHA-256 HMAC `code_digest`；旧明文 `code` 列已从运行数据库移除 | **已完成** |
| 验证码绑定邮箱和用途 | 唯一键为 `(email, purpose)`，用途只允许 `register` 或 `reset` | **已完成** |
| 记录有效期、失败次数、最大次数和消费时间 | 表中包含 `expires_at`、`attempt_count`、`max_attempts`、`consumed_at` | **已完成** |
| 错误验证码累计失败次数，到达上限后失效 | 默认最多 5 次；第 5 次错误后，即使随后提交正确验证码也会被拒绝 | **已完成** |
| 过期、用途不符、已消费验证码全部拒绝 | 底层隔离测试和 HTTP 路由测试均已覆盖 | **已完成** |
| 注册和密码重置原子消费 | 验证、条件消费和创建用户／更新密码位于同一个 SQLite `IMMEDIATE` 事务 | **已完成** |
| 并发或重复提交只能成功一次 | 并发注册和并发重置结果均为一个 200、一个 400；会话版本只增加一次 | **已完成** |
| API 和审计日志不泄漏验证码 | 对本轮全部验证码扫描响应和审计记录，无匹配值 | **已完成** |

NQ-P1-003 已达到验收标准。

## 修改位置

| 文件 | 修改内容 |
|---|---|
| `lib/verification-codes.js:1` | 新增验证码领域模块：安全生成、HMAC 摘要、定时比较、签发、精确撤销、失败计数和原子消费。 |
| `lib/db.js:32` | 新建库使用安全验证码结构。 |
| `lib/db.js:193` | 旧表迁移：删除明文结构并使旧验证码失效，然后建立有效期索引。 |
| `app/api/send-code/route.js:60` | 邮件内容使用临时明文，数据库只保存摘要；发送失败只撤销本次签发记录，避免误删并发生成的新码。 |
| `app/api/auth/register/route.js:42` | 验证码消费与用户创建进入同一立即事务，并在事务内再次检查用户名和邮箱冲突。 |
| `app/api/auth/register/password/route.js:37` | 独立密码重置路由使用原子消费，并在同一事务中更新密码和递增 Session 版本。 |
| `app/api/auth/login/route.js:47` | 旧登录兼容重置路径也改用同一安全消费逻辑。 |
| `.env.example` | 新增 `VERIFICATION_CODE_SECRET`；未单独设置时复用至少 32 字符的 `JWT_SECRET`。 |

HMAC 输入包含版本、用途、标准化邮箱和验证码。相同数字验证码用于不同邮箱或不同用途时会得到不同摘要。摘要比较使用 `crypto.timingSafeEqual`。

## 数据迁移

修改前已通过 SQLite 在线备份生成：

`backups/data-before-p1-verification-code-20260922.db`

启动迁移检测旧 `code` 列。发现旧结构时会建立新表、删除旧表并原子改名。历史未完成验证码不会迁移，因为将旧明文凭证继续带入新结构会保留原风险；用户需要重新获取验证码。

迁移后的运行表字段为：

```text
id, email, purpose, code_digest, expires_at,
attempt_count, max_attempts, consumed_at, created_at
```

数据库检查结果：`quick_check=ok`，`foreign_key_check=0`，旧 `code` 列数量为 0。

## 测试证据

### 底层安全与事务测试

25/25 项通过，覆盖：

- 六位数字格式和 64 位十六进制 HMAC。
- 数据库不存在明文验证码列和值。
- 注册/重置用途隔离。
- 错误尝试递增和第 5 次锁定。
- 过期拒绝、消费时间、重放拒绝。
- 业务回调异常时，业务写入和验证码消费同时回滚。
- 新验证码覆盖旧验证码后，旧邮件发送失败不能撤销新验证码。

### HTTP 路由测试

23/23 项通过，覆盖：

- 两个并发注册请求只有一个成功，只创建一个用户。
- 两个并发密码重置请求只有一个成功，Session 版本只增加一次，只有一个新密码生效。
- `/api/auth/login` 中的兼容重置路径成功一次后拒绝重放。
- 注册验证码不能用于密码重置，也不会因此被消费。
- 所有相关响应包含请求 ID；审计事件存在。
- 测试验证码没有出现在 API 响应或审计日志中。

测试结束后已删除全部临时用户、验证码、审计记录和限流桶。数据库再次确认临时用户和验证码均为 0。

## 已知边界

本轮没有向真实外部邮箱发送测试邮件。邮件成功后的签发响应已通过代码检查，发送失败的精确撤销已通过底层测试；真实 SMTP 投递仍需在部署环境使用测试邮箱验证。

修改 `VERIFICATION_CODE_SECRET` 或其回退使用的 `JWT_SECRET` 会立即使尚未消费的验证码失效，这是密钥轮换时的预期行为。生产环境应把该密钥放入密钥管理系统，不应写入仓库。
