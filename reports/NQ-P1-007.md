# NQ-P1-007 上传安全、配额与孤儿回收修复报告

复核日期：2026-09-26

## 问题与结论

修复前上传接口只检查文件名扩展名和体积。攻击者可以把脚本、压缩包或系统可执行内容改名为图片/EA；图片没有实际解码；`.zip` 和 `.mq5` 可承载任意内容；上传记录没有内容摘要、扫描状态或过期时间；未绑定文件没有数量/容量配额；产品替换和删除后的旧文件不会进入回收。

本项已完成代码安全基线：图片必须经过 Sharp 实际解码、尺寸限制和无元数据重编码；EA 只接受文件头与扩展名匹配的编译 `.ex4/.ex5`，关闭 `.zip/.mq5`；生产环境必须由外部扫描器返回 clean，否则 503 且不落盘；增加 SHA-256 去重、原子配额、24 小时孤儿过期、产品所有权/类型/未占用条件绑定以及替换/删除释放。

外部恶意软件扫描服务本身未在本机部署，结论为 **代码接入和失败关闭已完成，真实扫描引擎与告警联调未确认**。

## 内容策略

### 图片

- 仅允许 PNG、JPEG、WebP。
- 扩展名必须与解码后的真实格式一致。
- 单文件最大 2 MiB。
- 只允许单帧图片。
- 宽和高分别不超过 4096。
- 总像素不超过 16,777,216。
- 根据服务端检测到的格式重新编码，原始元数据和附加尾部载荷不会原样保存。
- 输出统一使用服务端随机文件名。

### EA

- 仅允许编译产物 `.ex4` 和 `.ex5`。
- 文件至少 64 字节。
- 前三个字节必须分别匹配 `EX4` 或 `EX5`。
- `.zip` 和 `.mq5` 已关闭，避免压缩包路径/嵌套内容和源脚本进入下载资产。
- 单文件最大 20 MiB。
- 仅 developer/admin 可上传。
- EA 始终写入非公开的 `storage/private/eas`。

文件头校验只能证明基础格式，不等同于恶意软件检测。因此生产环境另外要求扫描服务。

## 扫描与失败关闭

生产环境读取：

- `UPLOAD_SCAN_URL`
- `UPLOAD_SCAN_TOKEN`（可选 Bearer Token）

扫描器接收原始字节、编码后的文件名和 SHA-256，并必须返回 HTTP 2xx JSON `{ "clean": true }`。以下情况均拒绝上传且不保留文件或数据库记录：

- 未配置扫描器；
- 扫描服务超时或不可达；
- 非 2xx 响应；
- 无效 JSON；
- 未明确返回 `clean: true`；
- 返回恶意或拒绝结果。

本轮验证了扫描器未配置时返回 503 `SCANNER_UNAVAILABLE`，以及模拟扫描器返回 malware 时拒绝落盘。真实扫描引擎、测试病毒样本和生产告警仍须在部署环境验收。

## 配额与生命周期

每个账户的当前上限：

- 未绑定上传最多 10 个；
- 未绑定文件合计最多 50 MiB；
- 所有未删除文件合计最多 250 MiB；
- 图片 2 MiB/个；
- EA 20 MiB/个；
- 原有 20/10 分钟、100/天用户上传限流和来源限流继续生效。

最终配额复核和上传行插入位于 SQLite `IMMEDIATE` 事务内，并发请求不能仅靠同时通过预检查绕过配额。相同用户、类型和 SHA-256 受唯一索引保护。

未绑定文件创建时获得 24 小时有效期。上传请求和 `npm run upload:cleanup` 都会处理过期记录。产品替换或删除会解除旧文件绑定并重新设置 24 小时期限；清理时安全定位服务端文件名、删除文件并将数据库状态标记为 deleted。

## 运维与剩余边界

1. 正式部署前必须提供真实 `UPLOAD_SCAN_URL`，用扫描器厂商的 benign/EICAR 等标准测试流程验证允许和阻断结果，并确认审计告警；在此之前生产上传会失败关闭。
2. 将 `npm run upload:cleanup` 配置为定时任务，不能只依赖新上传触发清理。
3. 当前图片保存在 `public/uploads`，部署必须使用持久卷或对象存储；无状态实例本地磁盘不适合生产。
4. 当前 EX4/EX5 头校验基于现有真实 EX5 样本和格式标识。不同编译器版本若产生不同头，应先收集合法样本、更新检测器和测试，再开放。
5. 项目仍是明确的单实例 SQLite 基线。多实例部署需要把配额、元数据、对象存储和扫描任务迁移到共享基础设施。
