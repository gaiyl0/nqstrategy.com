# NQ-P2-001 策略指标矩阵与回测曲线修复报告

复核日期：2026-09-27

## 问题与验收标准

修复前产品只保存 `win_rate` 和 `drawdown` 两个自由文本。开发者可以填写任意字符串，平台无法计算、比较或确认数据范围；没有初始资金、净利润、Profit Factor、Sharpe Ratio、Recovery Factor、交易次数、净值曲线、回撤曲线和月度收益；管理员也看不到一套完整指标再决定是否上架。

本项验收标准：开发者能提交完整结构化指标；服务端统一验证金额、比例、点数、日期顺序和曲线一致性；管理员审核前数据不公开，编辑后撤销既有审核；市场详情页展示指标矩阵、净值曲线、回撤曲线和月度收益；页面明确区分“管理员审核展示”和后续 Nexus 实盘认证。

## 数据结构

新增一对一 `strategy_metrics` 表，以 `product_id` 为主键并级联关联产品，保存：

- Initial Deposit；
- Net Profit；
- Profit Factor；
- Sharpe Ratio；
- Max Drawdown；
- Recovery Factor；
- Win Rate；
- Trades；
- Equity Curve；
- Drawdown Curve；
- Monthly Returns；
- 提交、修改、审核时间；
- 审核管理员 `user_id`。

历史产品不伪造缺失指标。实际数据库原有 3 个 active 产品继续显示旧版胜率和回撤，并在详情页明确标记“旧版策略尚未补交结构化回测数据”。这些产品重新编辑时必须提交完整指标并重新进入审核。

## 服务端规则

`createProductSchema` 和 `updateProductSchema` 使用严格 Zod 对象验证完整 `metrics`：

- 初始资金：1 至 10 亿；
- 净利润：负 10 亿至 10 亿；
- Profit Factor：0 至 1000；
- Sharpe Ratio：负 100 至 100；
- 最大回撤和胜率：0% 至 100%；
- Recovery Factor：负 1000 至 1000；
- 交易次数：1 至 1000 万的整数；
- 净值和回撤曲线：各 2 至 2000 点；
- 月度收益：1 至 240 个月；
- 所有日期/月份必须严格递增且不能重复；
- 最大回撤必须与回撤曲线的最大值一致；
- 净值不能为负，回撤不能超过 100%，月度亏损不能低于 -100%；
- 未声明字段由 strict schema 拒绝。

API 只从通过 schema 的对象映射数据库字段，旧的自由文本胜率和回撤由结构化指标自动生成，不能单独伪造。非法指标在产品事务和上传文件占用之前返回 400。

## 审核与公开边界

1. 开发者创建或编辑产品时写入结构化指标，`reviewed_at` 和审核人保持空值。
2. 产品仍处于 `pending`，公共 API 不返回未审核指标。
3. 管理员只有在产品存在完整指标时才能批准；缺少指标返回 409。
4. 批准操作在同一事务中记录审核时间、审核管理员，并把产品改为 active。
5. 公开 API 只为已审核指标返回完整对象。
6. 开发者再次编辑会把产品退回 pending，并原子清除指标审核时间和审核人。
7. 管理后台显示核心指标和三组曲线点数，审批失败会展示服务端错误，不再无条件提示成功。

公开数据带有固定披露类型：

```text
developer_submitted_admin_reviewed
```

页面明确说明：数据由开发者提交，管理员审核只覆盖格式与上架展示，不代表 Nexus 实盘认证、收益承诺或独立审计。正式的实盘可信认证属于后续 NQ-P2-002。

## 前端功能

开发者发布/编辑页新增：

- 8 项结构化指标输入；
- `日期,净值` 多行净值数据；
- `日期,百分比` 多行回撤数据；
- `月份,百分比` 多行月度收益；
- 中英文格式提示；
- 最大回撤和曲线一致性提示。

产品详情页新增：

- 8 项指标矩阵；
- 响应式 SVG 净值折线图；
- 响应式 SVG 回撤折线图；
- 可横向滚动的月度收益柱状图；
- 管理员审核时间；
- 数据来源和风险披露；
- 历史产品缺失结构化数据提示。

没有引入新的图表依赖，曲线由项目自身组件绘制。
