# NQ-P2-004 修复报告：EA 试用授权、账号/设备绑定与到期策略

完成日期：2026-09-28  
状态：已完成授权模型、下载门禁、短期令牌、生产运行时回归、生产构建和实际数据库迁移。

## 问题与验收标准

旧系统把“订单”和“授权”视为同一件事，没有试用、到期、撤销、运行账号、设备绑定和 EA 运行验证协议。下载后的 EX4/EX5 可被复制；只限制网站下载不能限制程序实际运行。

验收要求：建立永久/试用授权；试用期限由服务器决定且重复请求不能续期；绑定信息不保存明文；换绑受次数和冷却限制；到期或撤销后下载和令牌校验失败；提供短期签名令牌与独立验证端点；明确只有 EA 集成验证代码后才能限制运行。

## 已完成修复

### 授权与绑定数据模型

新增 `product_licenses`，区分 `purchase`、`free`、`trial`。永久授权必须关联有效订单且无到期时间；试用必须绑定创建时的具体已发布版本、具有服务器到期时间且没有订单。数据库局部唯一索引保证同一用户对同一产品一生只能生成一条试用记录。

新增 `license_bindings` 和 `license_binding_events`。交易账号与设备指纹使用独立 HMAC 密钥生成不可逆摘要，公开和管理界面只显示脱敏账号或摘要前缀。每种绑定同一时间只能有一条 active 记录。

### 试用状态机

开发者可为产品开启 1–30 天试用。用户申请时服务端检查产品活动状态、当前已发布版本、自有产品、永久拥有状态和历史试用记录。开始时间与到期时间只由服务器写入。

重复申请返回原试用及 `replayed=true`，不会更新 `starts_at` 或 `expires_at`。过期试用保留为历史记录，不能重新领取或通过重放延长。

### 永久授权

免费订单或未来经可信支付验证的付费订单完成时，订单事务同时创建永久 license。旧数据库中的有效订单通过一次性迁移转为永久授权。订单继续代表交易事实，license 代表下载与运行权利。

### 下载门禁

下载不再只检查订单，而是要求有效 license：

- 永久授权继续结合具体订单和版本升级政策判断；
- 试用授权必须先完成交易账号和设备两类绑定，且只允许下载试用开始时锁定的版本；
- `expires_at <= 当前服务器时间` 立即失效；
- revoked 授权立即失效；
- 作者和管理员仍保留维护下载能力。

成功下载继续记录具体产品版本和订单；试用下载没有伪造订单 ID。

### 账号与设备绑定

支持绑定数字 MT4/MT5 账号和至少 16 字符的设备指纹。数据库不保存输入原文。相同绑定重复提交为幂等重放。

首次绑定不消耗换绑额度。后续换绑：

- 每种绑定最多换绑两次；
- 两次换绑之间至少间隔 7 天；
- 换绑时旧绑定标记 replaced；
- license 的 `token_version` 自增，使之前签发的令牌立即失效；
- 事件表保留旧绑定 ID、新绑定 ID、操作者和时间。

### 短期签名令牌

`POST /api/licenses/token` 要求登录 Session、有效授权、匹配的交易账号和设备，签发最长 15 分钟的 HMAC 令牌。试用令牌不会超过试用到期时间。令牌包含 license、用户、产品、可选版本、token version、签发/到期时间和随机 JTI，不包含裸账号或设备指纹。

`POST /api/licenses/verify` 面向 EA 客户端，不依赖浏览器 Cookie。它要求 JSON、可信代理来源限流和有效签名令牌，并再次实时检查数据库授权状态、token version、到期时间及账号/设备摘要。错误原因只以统一 401 对外返回，精确原因进入审计。

该端点被明确列为“签名令牌认证端点”，因此不要求浏览器 Origin；其他 Cookie 写接口的 CSRF 防护保持不变。

### 管理与用户界面

市场对开启试用的产品显示试用天数。用户个人中心显示全部永久/试用授权、状态、版本、到期时间和脱敏绑定，可绑定账号/设备、获取 15 分钟令牌及下载有效试用版本。

管理员新增“授权管理”，可查看授权、绑定摘要、状态和到期时间，并填写原因撤销。撤销会增加 token version，使现有令牌立即失效。

界面明确披露：网站授权与下载限制本身不能阻止已下载程序被复制；必须在 MQL4/MQL5 EA 内集成 Nexus 令牌获取/验证和失败停止逻辑后，才能限制程序实际运行。

## 生产配置

正式启动新增两个强制密钥：

- `LICENSE_SIGNING_SECRET`：签署短期令牌；
- `LICENSE_BINDING_SECRET`：账号与设备绑定 HMAC。

两者在生产环境均要求至少 32 字符。缺失或过短时生产构建/启动失败。更换绑定密钥会导致现有绑定无法匹配；更换签名密钥会使现有短期令牌失效，因此必须纳入 Secret 备份和轮换流程。

## 边界

- 当前已经实现网站下载授权和可供 EA 调用的验证协议，但现有 EX4/EX5 二进制是否调用该协议无法由网站自动修改。开发者必须在 EA 源码中集成后重新编译并发布新版本。
- 设备指纹的生成质量取决于未来 EA 客户端实现；网站只接受、校验长度并做不可逆摘要，不宣称设备指纹绝对不可伪造。
- 15 分钟令牌在有效期内可重复验证，这是离线容错与撤销时效的折中；换绑或管理员撤销会通过 token version 立即作废。
- 当前真实支付仍关闭。未来付费订单只能在可信结算完成后创建 purchase license。
- 正式数据库迁移框架仍留在 NQ-P1-010，本次使用数据库备份和一次性迁移标记。
