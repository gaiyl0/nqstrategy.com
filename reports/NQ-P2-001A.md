# NQ-P2-001A 修复报告：MT5 回测证据包与交叉核验

完成日期：2026-09-27  
状态：已完成代码基线；外部 OCR 与恶意文件扫描服务仍需在部署环境配置并现场验收。

## 问题与验收标准

原 NQ-P2-001 允许开发者直接填写净值、回撤和统计指标，无法证明数值来自 MT5。截图本身仍可被修改，因此本项把截图定位为“管理员审核过的回测证据”，不把它宣传为实盘认证。

验收标准：新策略必须提交 MT5 设置页、统计页和净值曲线页；原图不得进入公开目录；系统记录原图摘要并生成安全预览；自动提取失败时不得自动通过；管理员逐项审核；产品批准前，统计证据必须有可核对字段并与结构化指标一致。

## 已完成修复

1. 新增 `strategy_evidence`，使用稳定 `owner_user_id` 和 `product_id` 关联，限制证据类型、提取状态和审核状态；同一产品每种证据最多一份。
2. 新增 `/api/evidence`：仅 developer/admin 可上传；限制 PNG/JPEG/WebP 和 8MB；实际解码、像素/单帧限制、恶意扫描、SHA-256 去重；原始字节保存于私有目录，预览经 Sharp 旋转、缩放和 PNG 重编码以移除元数据。
3. OCR 采用可插拔 `EVIDENCE_OCR_URL`。服务缺失、超时或异常时状态为 `manual_review`/`failed`，不会自动批准。返回字段、字段名、值类型、长度和置信度都经过白名单式清理。
4. 创建或编辑产品必须绑定 3–4 份属于当前开发者且未被其他产品占用的证据，必含 settings、statistics、chart，可选 analysis。
5. 管理员逐证据批准或拒绝。统计 OCR 缺失时必须人工录入校正 JSON，重复审核使用条件更新返回 409，不会第二次改变状态。
6. 产品上架前要求三类必需证据全部批准，并将 statistics 提取的初始资金、净利润、Profit Factor、Sharpe、最大回撤、Recovery Factor、胜率、交易数与结构化指标交叉核对；交易数严格相等，其他数值允许 0.5% 或 0.01 的显示舍入误差。
7. 公共 API 和市场页只展示已批准证据的安全预览、类型和 SHA-256 前缀；原图路径和存储名不返回。证据说明明确提示截图可修改，审核不等于 Nexus 实盘认证。
8. CSRF 内容类型规则加入 `/api/evidence` multipart 例外；上传与审核写入现有限流和审计体系。
9. 未绑定证据超过 24 小时会在后续上传时回收；删除无购买记录的产品时同步删除私有原图和预览，避免数据库级联后遗留文件。
10. 修复刷新后的重复上传恢复：同一账号再次选择尚未绑定、仍安全有效且磁盘文件存在的相同 EA、图片或 MT5 证据时，接口返回原 URL/证据 ID 和 `resumed: true`，前端继续完成产品提交；已经绑定、已审核、已拒绝或文件丢失的记录不会被恢复。
11. 修复证据审核的 CSRF 内容类型误判：`POST /api/evidence` 仍强制 multipart，`PATCH /api/evidence` 改为强制 JSON。后台总批准按钮在 settings、statistics、chart 未全部审核前禁用并显示待办提示。

## 边界和待部署事项

- OCR 只能证明“图片中显示了什么”，不能证明图片未被事先修改；因此不会自动授予实盘认证。
- `EVIDENCE_OCR_URL` 和 `EVIDENCE_OCR_TOKEN` 尚未配置生产服务。未配置时管理员可人工校正统计字段，系统保持人工审核状态。
- `UPLOAD_SCAN_URL` 在生产环境必须可用，否则证据上传失败关闭。
- 更高可信等级应在后续 Nexus Verification 中接收 MT5 原始 HTML 报告、交易明细和参数文件，验证报告哈希与统计一致性，并进一步支持可复现实验、平台复跑或只读实盘连接。
