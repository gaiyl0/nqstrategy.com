## 数据库

新增三个表：

- `product_favorites`：复合主键 `(user_id, product_id)`；
- `developer_follows`：复合主键 `(follower_user_id, developer_user_id)`，数据库 CHECK 禁止关注自己；
- `product_ratings`：复合主键 `(user_id, product_id)`，评分 CHECK 为 1–5，评价最多 1000 字。

所有身份关联均使用稳定整数 ID 和外键。用户或产品真正删除时社交记录级联删除；当前账户注销采用匿名化保留原 ID，同名重注册会获得新 ID，因此不会继承旧收藏、关注或评分。

迁移后数据库快照：`backups/data-after-p2-006-social-20260928.db`。

为产品、开发者和评分聚合查询建立索引。实际数据库 `quick_check=ok`，`foreign_key_check=[]`。

## 服务端业务规则

新增 `lib/social.js`：

- 收藏和关注使用 `INSERT ... ON CONFLICT DO NOTHING`，重复请求不重复累计；
- 评分使用 UPSERT，同一用户修改评分时更新原行；
- 评分资格从 `product_licenses` 服务端查询；
- 只接受 `purchase/free`、`active`、永久授权；
- `trial` 授权不能评分；
- 产品作者不能评价自己的产品；
- 下架或不存在的产品不能收藏或评分；
- 只能关注仍存在且角色为 developer/admin 的开发者；
- 公开聚合只含平均分、评分数、收藏数和作者关注数；
- 未登录公开响应不含评分人身份；
- 登录用户只额外取得自己的收藏/关注/评分状态。

## API 安全

新增 `/api/social`：

- GET：要求 Session，返回当前用户收藏、关注和评分；
- POST：执行收藏、关注或评分；
- 使用 Zod 判别联合 schema，拒绝未知字段和混合动作；
- 写操作经过现有 Proxy CSRF/Origin 与 JSON Content-Type 门禁；
- 每用户每小时 60 次持久化限流；
- 所有成功、失败和限流结果进入 HMAC 链式审计；
- 审计不记录评价正文等内容；
- 对外错误按 401/403/404/409/429/500 分类。
